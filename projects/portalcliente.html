Portal Cliente

Una plataforma B2B que centraliza la gestión documental, laboral y fiscal de una asesoría y la pone a disposición de sus clientes en un portal único.

2025–26 · Vue 3 · TypeScript · Python · FastAPI · MariaDB · Docker

El proyecto

Portal Cliente nace de la necesidad de modernizar la relación entre las asesorías y sus clientes. En Diagram Software desarrollamos esta plataforma para reemplazar un sistema antiguo y ofrecer una experiencia web moderna, centralizada y escalable.

Trabajé como desarrollador full-stack durante casi un año: diseño e implementación del frontend con Vue 3 + TypeScript, del backend con FastAPI + Python, y la migración progresiva desde el monolito PHP existente.

Módulos de la plataforma

Portal del cliente

Cada cliente accede a su propio panel con documentos, expedientes y solicitudes asignadas por la asesoría.

Gestión laboral

Nóminas, contratos, cartas de variación, finiquitos, informes de costes y más, integrado con AvanzaPi.

Expedientes y solicitudes

Sistema de casos con hilos de conversación, adjuntos y operaciones en lote entre asesoría y cliente.

Altas de empleados

Flujo asíncrono con Celery para registrar empleados vía API externa, con estados y notificaciones en tiempo real.

Permisos por asesoría y cliente

Roles y permisos por asesoría y por cliente, con alcances de administrador global, asesor y cliente.

Tablón de noticias

Publicaciones internas filtradas por departamento y publicación programada con Celery beat.

Arquitectura

El backend sigue una arquitectura por capas (routes → services → repositories → adapters) con un módulo independiente por dominio de negocio. El frontend replica esa organización con módulos de páginas, componentes, composables y rutas.

web (Vue 3 + TS)
├─ auth, clients, laboral
├─ expedientes, solicitudes
├─ fiscal, contabilidad
└─ altas, tablon_noticias
api (FastAPI + Python 3.13)
├─ módulos espejo (routes → service → repo)
├─ JWT + permisos por cabecera (X-Adviser-Id, X-Client-Id)
├─ Celery + Redis (tareas asíncronas)
└─ Sentry + Prometheus (observabilidad)
db
├─ MariaDB (datos principales)
└─ réplica MySQL (datos del sistema antiguo)

La autenticación es por JWT con tokens de acceso y refresco. El multi-tenancy se resuelve con cabeceras HTTP (X-Adviser-Id, X-Client-Id) que determinan el alcance de los datos en cada petición.

Las tareas pesadas (altas vía AvanzaPi, avisos de nóminas, publicación diferida de noticias) se procesan en segundo plano con Celery + Redis, y el frontend recibe las actualizaciones en tiempo real por WebSockets.
