SaaS para asesorías · Multi-Tenant

Portal Cliente

Una plataforma B2B que centraliza la gestión documental, laboral y fiscal de una asesoría y la pone a disposición de sus clientes en un portal único.

Vue 3 TypeScript Python FastAPI MariaDB Docker

El proyecto

Portal Cliente nace de la necesidad de modernizar la relación entre las asesorías y sus clientes. En Diagram Software desarrollamos esta plataforma para reemplazar un sistema legacy y ofrecer una experiencia web moderna, centralizada y escalable.

Trabajé como full-stack developer durante casi un año, participando en el diseño e implementación completos del frontend con Vue 3 + TypeScript y del backend con FastAPI + Python, así como en la migración progresiva desde el monolito PHP existente.

Módulos de la plataforma

Portal del cliente

Cada cliente accede a su propio dashboard con documentos, expedientes y solicitudes asignadas por la asesoría.

Gestión laboral

Nóminas, contratos, cartas de variación, finiquitos, informes de costes y más, todo integrado con AvanzaPi.

Expedientes y solicitudes

Sistema de casos con hilos de conversación, adjuntos y operaciones en lote entre asesoría y cliente.

Altas de empleados

Flujo asíncrono con Celery para el registro de empleados vía API externa, con estados y notificaciones en tiempo real.

RBAC multi-tenant

Roles y permisos granularmente escalados por asesoría y por cliente, con alcances de administrador global, asesor y cliente.

Tablón de noticias

Publicaciones internas con filtro por departamento y publicación programada mediante tareas Celery beat.

Arquitectura

El backend sigue una arquitectura por capas (routes → services → repositories → adapters) con módulos independientes para cada dominio de negocio. El frontend replica esta organización con módulos de páginas, componentes, composables y rutas.

# Diagrama de arquitectura simplificado
web (Vue 3 + TS)
├─ auth, clients, laboral
├─ expedientes, solicitudes
├─ fiscal, contabilidad
└─ altas, tablon_noticias
api (FastAPI + Python 3.13)
├─ módulos espejo (routes → service → repo)
├─ JWT auth + RBAC por header (X-Adviser-Id, X-Client-Id)
├─ Celery + Redis (tareas asíncronas)
└─ Sentry + Prometheus (observabilidad)
db (MariaDB + MySQL replica)
├─ MariaDB (datos principales)
└─ MySQL replica (DS Replica — datos legacy)

La autenticación es por JWT con tokens de acceso y refresco. El multi-tenancy se resuelve mediante cabeceras HTTP (X-Adviser-Id, X-Client-Id) que determinan el alcance de los datos en cada petición.

Las tareas pesadas (registro de empleados vía AvanzaPi, notificaciones de nóminas, publicación diferida de noticias) se procesan de forma asíncrona con Celery + Redis, y el frontend recibe actualizaciones en tiempo real mediante WebSockets.

Stack tecnológico

Frontend

  • Vue 3 + Composition API + TS
  • Vite + Tailwind CSS 4
  • Pinia (estado) + Vue Router
  • vue-i18n (ES / EN / CA / DE)
  • Tiptap (editor rich text)

Backend

  • FastAPI + Python 3.13
  • SQLAlchemy + Alembic
  • MariaDB + MySQL (DS Replica)
  • Celery + Redis (tareas async)
  • JWT + WebSockets + Sentry
